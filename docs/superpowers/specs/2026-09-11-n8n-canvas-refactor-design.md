# n8n 风格工作流画布重构设计

**日期：** 2026-09-11  
**状态：** 已获用户批准  
**范围：** React 工作流编辑器的画布、节点、连线、检查器和编辑命令

## 1. 目标

把现有 React/XYFlow 编辑器提升为一个可实际编排 Telegram 自动化的工作台：节点可添加、移动、复制、删除和批量选择；连线可创建、编辑、删除和重连；配置编辑有清晰的校验反馈；常用操作具备 n8n 风格的工具栏、命令菜单和快捷键。

## 2. 已确认的参考行为

已在正式 n8n 实例中实际操作并核对：

- 新建工作流、添加手动触发器和内置节点；新节点会自动连接到当前选中节点。
- 双击节点打开参数编辑器；参数区分 `Parameters`、`Settings` 和输入/输出区域。
- 节点悬停显示执行、停用、删除和更多操作；更多操作包含复制、复制节点、重命名、选择全部、整理画布等命令。
- 从节点端点拖拽创建直连和分支连线；选择连线后显示添加节点、删除连接等操作。
- 节点可拖动，画布支持缩放、适配画布、缩略图和命令栏。

临时审计工作流已恢复为三节点、两条连线，原始 `My workflow` 未修改。

## 3. 现状与缺口

现有实现已经具备 canonical workflow JSON、React Flow 画布、节点库、拖入添加、基础检查器、导入导出、草稿保存、保存/运行和现有回归测试。主要缺口是：

- 选择模型只有单节点/单连线，缺少 Shift 多选和批量删除；
- 没有可发现的节点/连线上下文工具栏，连接点不能直接打开添加节点流程；
- 连线只能新建和删除，不能安全重连；
- 没有撤销/重做、复制/粘贴/复制节点、命令菜单；
- 节点配置只有字段渲染，没有统一的必填/范围/正则反馈和更好的高级配置折叠；
- 运行按钮只有全局 loading/Toast，没有画布级运行状态；
- `App.jsx` 同时承担数据请求、画布状态、编辑器渲染和登录，边界过宽。

## 4. 设计决策

### 4.1 不改变领域契约

保留 React 18、`@xyflow/react`、现有 Python API、工作流 JSON Schema、Node-RED 兼容桥和后端执行器。所有新交互仍通过 `flowToDocument` / `documentToFlow` 写回 canonical JSON；节点位置和 viewport 继续写入非执行性的 `ui` 字段。

不新增依赖。浏览器剪贴板使用内存 clipboard，避免把工作流配置写入系统剪贴板或 localStorage。

### 4.2 最小清晰的前端边界

- `App.jsx`：认证、服务端数据、当前工作流、历史栈和跨页面动作。
- `flowModel.js`：纯的图转换、连线校验、批量删除和复制数据处理。
- `workflowHistory.js`：有上限的纯撤销/重做栈。
- `WorkflowNode.jsx`：节点视觉、状态、节点工具栏和端点添加按钮。
- `WorkflowEdge.jsx`：连线路径、选中态、分支条件和连线工具栏。
- `WorkflowInspector.jsx`：节点/连线检查器和表单校验提示。
- `WorkflowCanvas.jsx`：节点库、画布、命令/上下文菜单和 React Flow 事件绑定。

这些文件只拆已有职责，不建立通用状态框架或新的领域层。

### 4.3 编辑交互

- 单击节点选择；Shift/Command 单击切换多选；单击空白清除选择。
- 双击节点打开右侧检查器并保留当前选择。
- 节点顶部工具栏提供执行、复制、更多/删除；端点旁的 `+` 打开节点选择器并自动创建出边。
- 选中连线显示 `+` 和删除按钮；在连线中插入节点时用两条新连线替换原连线。
- 连线端点支持重连；拒绝自连、重复 source-target 和不存在的端点，并通过 Toast 解释原因。
- 右键菜单和命令菜单提供相同的可执行命令，避免隐藏关键能力。

### 4.4 检查器与校验

继续使用现有节点配置字段和原始 JSON 入口。常用字段放在前面；高级字段和原始配置使用原生 `details` 折叠。校验是轻量的前端提示，不替代服务端校验：

- Telegram 节点：目标会话必填；消息节点文本必填；等待/读取条数为正整数；点击按钮匹配值必填；
- 条件节点：表达式必填；延迟秒数为非负数；变量名符合安全标识符；
- 校验错误显示在节点状态、检查器字段下方和保存前 Toast 中。

### 4.5 历史和执行状态

历史只记录语义编辑，不记录每个拖动帧；位置拖动在 `onNodeDragStop` 形成一个历史项。最多保留 50 个快照，undo/redo 只处理 flow，不影响服务端数据。保存仍是显式版本保存。

运行期间在节点上显示统一的 `running` 状态，运行结束显示最近一次成功/失败状态；不虚构后端尚未提供的逐节点执行结果。

## 5. 验收标准

1. 现有工作流打开后节点、边、条件、位置和 viewport 不变。
2. 从节点端点添加节点能自动创建有效连线；从边工具栏插入节点能替换原边。
3. 节点和边支持选中、移动、Shift 多选、复制/粘贴、复制、删除和撤销/重做。
4. 连线支持拖动端点重连，并拒绝自连和重复连线。
5. 检查器保留现有 Telegram、控制节点和原始 JSON 编辑能力，错误字段有即时提示。
6. 保存、运行、导入导出、账号和运行记录 API 契约不变。
7. `npm test`、`npm run build` 和 Python 相关测试通过。
8. 浏览器手工验收覆盖新建、编辑、串联、删除、保存、运行和恢复草稿。

## 6. 明确不做

- 不复制 n8n 的后端执行引擎、凭据系统或商业功能；
- 不增加任意脚本节点、自由 JavaScript 执行或新的表达式语言；
- 不把 Node-RED 兼容编辑器改成主执行器；
- 不引入全局状态库、拖拽库或组件库；
- 不删除正式 n8n 中用户已有工作流。
